# Changelog

All notable changes to **DartNative Go** will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.0.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Added
- **Assets & fonts server rewrite, on-demand native font registration, and client caching**:
  - Added ETag + `304 Not Modified` support across `/assets/...`, `/asset?path=...`, and `/fonts/<family>.ttf`, plus `/assets.json` and `/icon-fonts.json` endpoints.
  - Added `NativeFontRegistrar` (CoreText / native registration) and disk-cached `IconFontManager` for on-demand custom & external-package icon font loading (e.g. `lucide_kit`, `AndaleMono`).
  - Added persistent on-device disk caching (`AppCache`) for bundles, fonts, and assets with ETag-based stale asset invalidation and offline `FileImage` fallback in both AST and source asset bridges.
- **Launcher settings theme switcher & version stats (`dngo_ui`)**:
  - Added theme changer controls and `dngo` / DartNative / runtime version stats to `HostLauncher` settings.
- **Real-time LAN discovery goodbye packets & reconnect hook**:
  - `DartGoBroadcaster` now includes `appVersion` and `iconUrl` in discovery beacons and broadcasts an immediate UDP `bye` packet on `stop()` so the launcher drops offline servers without waiting for probe timeouts.
  - `DartGoNetworkScanner` handles `bye` packets immediately, updates launcher UI on `appVersion` / `iconUrl` metadata changes, and lowers `_offlineGrace` from 12 s to 6 s.
  - Added `LiveConnection.onReconnected` callback fired when a WebSocket reconnects after a drop.
- **Shared baked-in version constants** (`package:dngo_api/version.dart`):
  - `kDartGoVersion`, `kDartGoRuntimeVersion`, and `kDartNativeVersion` are generated by `tool/sync_versions.dart` from root `pubspec.yaml` + `dn_plugins.lock` (also run from `tool/install_global.dart` before compile).
  - `DartGoHost.dngoVersion` / `dartNativeVersion` / `runtimeVersion` expose them to interpreted host UI without relying on top-level constants that the bridge does not register.
  - Dev server `/manifest.json`, `/health`, and discovery payloads advertise the same snapshot via `DngoVersionInfo`.
- **Dev-server branding from `dngo.config.dart`**:
  - `AssetDetector` prefers app/platform icon + splash (+ background colors) from `dngo.config.dart`, then falls back to `dartnative_splash` / `dartnative.assets` / conventional paths.
  - Display `appName` / `appVersion` come from `dngo.config.dart` when present; pubspec `name` remains `packageName` for `package:` URIs and dep packaging.
  - Example app ships a seeded `dngo.config.dart` with icon/splash assets.
- **Browser loading interstitial** (`/_dngo/loading`): opening the printed Server URL in a browser redirects HTML navigations to a deep-link page; API clients still receive JSON identity at `/`.
- **Host launcher / DevTools UI**: recent-project management (`recentProjects`, `removeProject`), refreshed launcher cards/lists, and DevTools sheet version rows wired through the host bridge.
- **Native bottomsheet tutorial guide**: Added interactive lesson guide for `package:native_bottomsheet` (`example/lib/tutorials/native_bottomsheet.md`).
- **`local_auth_kit` and `quick_actions_kit` plugin integrations**:
  - Bridged `LocalAuthentication` and biometric enums for AST and source runtimes.
  - Bridged `QuickActions` and `ShortcutItem` for home screen shortcuts and action handlers.
  - Added demo screens (`LocalAuthDemo`, `QuickActionsDemo`) and headless test suite with `FakeLocalAuthHost`.
- **`dartnative_live_activities` plugin integration**:
  - Bridged `LiveActivities` and `LiveActivity` for both AST and source runtimes with full preset and custom layout support.
  - Added native iOS WidgetKit extension (`DartNativeWidgets`) and App Intents package for iOS 16.1+ Live Activities.
  - Configured app group entitlements (`group.beatcode.studio.dartnative`) and `NSSupportsLiveActivities`.
  - Added interactive demo (`LiveActivitiesDemo`), headless fake (`FakeLiveActivitiesHost`), and bridge suite.
- **Selective bridge regeneration (`--package`, `--module`, `--changed`)**:
  - Added `tool/d4rtgen_select.dart` allowing `tool/d4rtgen.dart` and `tool/d4rtgen_ast.dart` to target specific packages or modules instead of full regeneration.
  - Implemented fingerprint stamp tracking to skip unchanged packages and avoid rewriting shared barrels during partial runs.
  - Added generator post-fixes for Riverpod 3 skew (`StateNotifier`, `ProviderScope` type coercion, and member getters).
- **Upstream `playground/` runs headless on both engines**: the reference
  DartNative app is vendored as a fixture and covered by
  `test/playground/playground_headless_test.dart` (AST) and
  `test/playground/playground_source_headless_test.dart` (source). Both boot
  the real `main.dart` (registrant, Skia, SQLite pre-warm,
  Firebase/notifications, 43 `registerRoutes` calls, theme restore) and build
  **all 43 captured routes**; the AST suite also builds the five tab bodies.
  `_knownGaps` is empty and a route that regresses fails the suite. See
  `docs/architecture/playground-headless.md`.
- **Interpreted proxies for the remaining abstract bridge parameters**:
  `TickerProvider` (`AnimationController(vsync: this)` from
  `SingleTickerProviderStateMixin` / `TickerProviderStateMixin`),
  `CustomPainter` (`CustomPaint` / `CanvasSurface` painters) and
  `WidgetsBindingObserver` (`WidgetsBinding.instance.addObserver(this)`) are
  now materialised for interpreted subclasses in both engines
  (`InterpretedTickerProvider`, `InterpretedCustomPainter`,
  `InterpretedWidgetsBindingObserver`).
- **`Signal.watch` / `Computed.watch` bridged by hand**
  (`lib/src/interpreter/state_signal_extensions.dart`): the extension is
  declared on the library-private `_SignalBase`, so the generator skips it.
  Registered per public subclass on both engines; falls back to `.value` when
  there is no element to subscribe (headless builds).
- **`dart:io` `ProcessInfo` bridge** in both vendored engines
  (`stdlib/io/process_info.dart`, gated on `DangerousPermission`).
- **`dart:developer` stdlib for the source engine**
  (`third_party/tom_d4rt/lib/src/stdlib/developer*`): ported from the AST
  engine, so a guest importing `dart:developer` loads in source mode too.
- **`MediaGalleryFFIBindings` host bridge**
  (`lib/src/interpreter/media_gallery_ffi_bridge.dart`): the generator never
  emitted the class, so `MediaGalleryFFIBindings.loadSymbols()` in the
  playground's plugin registrant failed — fatally in source mode, where
  statically undefined names are rejected before a guest `try` can run.
- **Source-mode `runApp` capture**: `InterpreterRunner.evaluate` now waits
  briefly for a late `runApp`, matching `AstInterpreterRunner`, because the
  playground calls it from an async continuation.
- **Playground host fakes**: `fake_media_gallery_ast.dart`,
  `fake_connectivity_ast.dart` and `fake_audio_player_ast.dart` (each covering
  both engines) shadow the plugins whose FFI asserts on a host.
- **Bridges for the rest of the first-party plugin surface**:
  `dartnative_skia`, `_sqlite`, `_secure_storage`, `_hive`, `_social_sign_in`,
  `_firebase`, `_video_player`, `_audio`, `_permissions`, `_camera`,
  `_image_crop`, `_compressor`, `_supertonic_tts`, `_lottie` and
  `_onnxruntime` are now dependencies with modules in `buildkit.yaml` /
  `buildkit_ast.yaml` (both bridge sets regenerated). `kAstBridgedLibraries`
  covers their URIs plus `package:dartnative/canvas.dart`, which
  `dartnative.dart` does not re-export — the UI surface is registered under that
  URI by `registerDartNativeSubBarrels` / `registerAstDartNativeSubBarrels`.
- **Host bridges for native-binding entry points**:
  - `runZonedGuarded` (`zoned_guarded_bridge.dart`) keeps the catch-and-report
    contract without bridging `Zone`, so entrypoints that wrap `main()` boot.
  - `registerRoutes` (`routes_bridge.dart`) captures the route table in
    `D4rtRoutes` and coerces each interpreted closure into a native
    `WidgetBuilder` instead of hitting the host stub that throws.
- **`DnHarness.astBridgeOverrides`** (and `AstInterpreterRunner.runner`) so host
  fakes can shadow generated AST bridges, mirroring `bridgeOverrides` for the
  source engine. `fake_shared_preferences_ast.dart` is the first such fake.

- **Deep links (`dartnativego://open?url=<host:port>&name=<app>`)**: Launches the app directly into a guest project via `app_links_kit`, registered on iOS and Android. Added `dart_go open` CLI command with `--device` (simctl/adb dispatch) and `--qr` flags.
- **`R` hot-restart key in CLI dev server**: Uppercase `R` in `dart_go start` broadcasts a hot restart, dropping interpreter state and re-evaluating the current bundle from scratch.
- **Split app entrypoints for AST vs Source runtimes**: `lib/main.dart` links only the AST runtime, keeping ~690k lines of `package:analyzer` and source bridges out of release AOT compiles. Developer source runtime is accessible via `lib/main_source.dart`.
- **Server components (`@ServerComponent` / `@Server`)**:
  - Annotating a widget class makes it buildable as its own AST bundle, served on demand and hot-swappable OTA. Guests import the dependency-free `package:dartnative_go/server.dart`; the bundler injects the real annotation source, so no guest dependency is required.
  - `ServerComponentBundler` emits a per-component **delta** bundle containing only the modules that are *not* already in the client bundle, stopping at bridged libraries and deferred imports. `client-module-index.json` records the shared set so each delta stays small.
  - The dev server serves `/server-components/manifest.json`, `/server-components/<id>.ast` (id validated against `^[A-Za-z0-9_-]+$`) and `/client-module-index.json`, and advertises `hasServerComponents` / `serverComponentsUrl` in `/manifest.json` with absolute URLs.
  - On device, `ServerComponentView` fetches, instantiates and mounts the component against the *live* client interpreter, so shared imports resolve by reference. It supports props, a `fallbackComponentId`, loading/error builders, and remounts on prop change. `ServerComponentLoader` adds fingerprint-based caching, `forceReload`, `preloadAll` and a live server-URL provider.
  - Both engines are bridged (`server_component_bridge.dart`, `server_component_source_bridge.dart`), so interpreted guest code can mount a component declaratively; `package:dartnative_go/server_component.dart` is in `kAstBridgedLibraries` and never bundled.
  - `tool/export_server_components.dart` exports the artifacts to a CDN-ready directory with absolute URLs.
  - `test/server_component/` (delta subtraction, props, caching, uniqueness, missing deps, client-import resolution, source bridge) plus `test/server/server_components_endpoints_test.dart` and the headless `ServerComponentHarness` cover the load → render → reload cycle.
  - v1 discovery: the annotated module must be reachable from the guest entrypoint for the bundler to see the annotation. Server-only modules that are not reachable are still read from disk when a delta needs them.
- **`dio` compiled into the shell (AST + source bridges)**:
  - `dio` 5.x is now a bridged package in `buildkit.yaml` / `buildkit_ast.yaml` (generated `dio_bridges.b.dart`), so a guest importing `package:dio/dio.dart` receives the compiled host `Dio` and no longer interprets dio's request pipeline.
  - `package:dio/dio.dart` was added to `kAstBridgedLibraries` so the dev server skips it while bundling (its conditional `dart:io` / `dart:html` imports are not AST-safe).
  - `dio`'s `FormData.fromMap` defaults `boundaryName` to the private top-level const `_boundaryName`, which the generator cannot reference, so it emitted a mandatory-argument stub that threw whenever the parameter was omitted. Both generator drivers (`tool/d4rtgen.dart`, `tool/d4rtgen_ast.dart`) now post-fix the emitted bridge to inline the literal default, so a regeneration no longer reintroduces the throw.
- **Workspace layout**:
  - The root `pubspec.yaml` declares `workspace: [example]` and `example/` sets `resolution: workspace`, so a single `dn pub get` resolves both packages from one lockfile. `example/pubspec.lock` is no longer tracked.
  - Generated AST bundles (`example/assets/bundles/`) are gitignored instead of committed; `client-module-index.json` is a build artifact, not source.
  - `android/settings.gradle.kts` applies the Kotlin Compose compiler plugin (matching the Kotlin version), required by plugins whose Android module uses Jetpack Compose (`native_bottomsheet`).
- **Separate launcher & preview routes**:
  - The launcher is now the host `App`'s home route (`/`) and no longer swaps its child when a project opens; opening a project pushes a dedicated launch/preview route (`/preview`) that shows the splash then the mounted guest, and `Go Home` pops back.
  - Added `lib/src/preview/preview_route.dart` (`PreviewScreen` + `PreviewState`) driven by a host-owned `ValueNotifier`, so the pushed route stays in sync across launch, hot reload and errors without the root re-deciding its child.
- **DevTools visible across guest navigation**:
  - The floating DevTools surface is now the host `App`'s `builder` (the framework's full-screen layer above every route) instead of living inside a route, so it stays reachable while the guest pushes its own screens — and, unlike a root `Overlay` entry, its button receives taps.
- **Auto-connect on launch (headless testing)**:
  - The launcher now connects to the first online project the network scanner discovers, so the app reaches a mounted guest without a human tap — enabling simulator/CI automation (`dn run` + `tool/ui_test_run.dart`) to drive the app end-to-end.
  - Enabled by default in JIT/debug builds, disabled in AOT product builds; override either way with `--dart-define=DARTNATIVE_AUTO_CONNECT=true|false`. Runs at most once per app process, so returning to the launcher never causes a reconnect loop.
- **AST pure-Dart dependency compatibility**:
  - Added SDK collection-base and map-view bridges needed to interpret `collection` 1.19.1, including the dependency chain pulled in by `equatable` 3.0.0.
  - Expanded AST standard-library support for typed-data list views, conversion-sink aliases, `WeakReference`, and the host `Zone` observation/delegation API.
  - Added an AST runtime regression test exercising `Equatable` equality through the collection dependency.
- **AST initialization profiler**:
  - Added compile-time-gated `D4rtProfiler` setup measurements for bridge/stdlib registration, module-loader creation, and declaration passes. Enable with `--dart-define=D4RT_PROFILE_INIT=true`; it has no instrumentation cost when disabled.
- **AST library part support**:
  - AST mode now interprets a library's `part` files in the owning library environment, preserving shared private-name visibility for generated code such as `build_runner` output.
  - Parent library cache fingerprints include part URIs and content fingerprints so part-only edits reload the owning library.
  - Added regression tests for entrypoint parts, imported-library parts, and part-only cache invalidation.
- **Interpreted Guest Stack Traces**:
  - Implemented interpreted call frame tracking (`InterpretedCallFrame`) in `tom_d4rt_ast`.
  - Added line and column number resolution mapping from AST byte offsets to source code locations.
  - Formatted guest runtime errors to output standard Dart stack traces (`#0 Class.method (package:uri:line:col)`) pointing directly to interpreted guest application code rather than host interpreter internals.
- **DartNative Compatibility Bridge (`package:dartnative/flutter_compat.dart`)**:
  - Generated native and AST bridges (`DartnativeFlutterCompatBridge`) for `package:dartnative/flutter_compat.dart`.
  - Registered bridge in `buildkit.yaml`, `buildkit_ast.yaml`, `tool/d4rtgen.dart`, and `tool/d4rtgen_ast.dart`.
  - Added `package:dartnative/flutter_compat.dart` to `kAstBridgedLibraries` in `ast_builder.dart`.
  - Added `tool/d4rtgen_compat.dart` for isolated single-library bridge generation.
- **VS Code Debug Adapter Protocol (DAP) Server**:
  - Implemented embedded DAP server (`lib/src/dap/`) supporting line breakpoints, variable inspection, paused stack frames, step-in/out/over, and resume controls directly via standard IDE debuggers.
  - Added `--dap` flag in `dart_go start` to expose the DAP service.
  - Added VS Code launch configurations (`.vscode/launch.json`) and automated test coverage (`test/unit/dap_server_test.dart`).
- **Delta AST Patch Protocol (`/guest.ast.patch`)**:
  - Incremental code reloads now generate and transmit lightweight gzip delta AST bundles containing only modified compilation units (~20 KB vs 1.89 MB full bundle, a **99% network payload reduction**).
  - Added `AstBundle.applyPatch(AstBundle patch)` in `tom_d4rt_ast` for zero-allocation in-memory AST merging on device.
  - Reduced device AST JSON deserialization time from ~2,580ms down to **5–7ms** (**368× speedup**).
- **Dot Shorthands in SafeAstConverter**:
  - Added conversion support for `DotShorthandPropertyAccess` and `DotShorthandInvocation` in `SafeAstConverter`.
- **Zero-Manifest Fast-Path**:
  - Code-only reloads bypass `/manifest.json` completely, eliminating 300–500ms of HTTP roundtrip overhead.
  - Automatic asset change detection triggers manifest fetches only when `assets/` modifications occur.
- **Scale-Proof In-Memory DFS & Build Caching**:
  - Incremental DFS seeding in `AstBuilder` enables rebuild times of **12–19ms** across projects with 500 to 2,000+ modules.
  - Warm file hash caching initialized during server cold start.
- **Isolate & Background Compute**:
  - Integrated `IsolateWorker` bridge and stdlib isolate runtime (`isolate_compute_bridge.dart`, `isolate_worker.dart`).
- **Benchmarking & Testing Infrastructure**:
  - Added `tool/scale_inject.dart` to generate and clean synthetic realistic Cupertino modules for scale benchmarking.
  - Added `tool/benchmark_scale.dart` and `tool/benchmark_speed.dart` for automated AST generation and reload latency profiling.

### Fixed
- **Library-scope getters were returned instead of invoked** (`tom_d4rt_ast`):
  reading `kHomeBg` yielded the `InterpretedFunction`, so
  `Container(color: kTileBg)` received a function. `visitSimpleIdentifier` now
  invokes a library-scope getter.
- **A library getter and setter sharing a name clobbered each other**
  (`tom_d4rt_ast`): the second declaration overwrote the first, so
  `playgroundPalette` resolved to the setter function. Both halves are now kept
  in a `LibraryProperty`; reads invoke the getter, assignments the setter.
- **Interpreted `InheritedWidget` subclasses were not widgets**
  (`tom_d4rt_ast`): a guest theme wrapper failed its parent's build with
  `Invalid parameter "buildResult": expected Widget`. The new
  `InterpretedInheritedWidget` proxy wraps them, and the build paths prefer
  `wrapAstInterpretedWidget` over `extractBridgedArg<Widget>`.
- **Missing `assets/app-logo.png` broke `dn test` / `dn run`**: `pubspec.yaml`
  and three widgets referenced the app logo, but the file was never committed,
  so asset bundling failed with `No file or variants found for asset:
  assets/app-logo.png`. Added the file (the existing `assets/dartnative.png`
  brand mark).
- **AST bridge regeneration lost the sqlite `??>` patch**: `tool/d4rtgen_ast.dart`
  now applies it like the source driver, so formatting no longer fails on
  `dartnative_sqlite_bridges.b.dart`.

### Changed
- **The whole `tom_d4rt` family is now vendored under `third_party/`** and
  path-overridden from the root `pubspec.yaml`:
  - `tom_d4rt` 1.77.0 → **1.279.0**, `tom_d4rt_ast` 0.65.0 → **0.260.0**,
    `tom_d4rt_generator` 1.26.2 → **1.67.0**, `tom_d4rt_exec` 1.25.0 → **1.62.0**.
  - Toolchain moves with it: `analyzer` 10.2 → 14.5, `tom_ast_model` 0.2.2 →
    0.3.3, `tom_ast_generator` 0.2.11, `tom_build_base` 2.26.
  - `pkgs/tom_d4rt_ast` moved to `third_party/tom_d4rt_ast`; its patch list is
    in that package's `pubspec.yaml` header.
  - Our AST-engine patches were re-ported onto upstream 0.260.0 (new AST model):
    hot-reload cells (`DeclarationRegistry`, `ClassCell`, `FunctionCell`,
    `VariableCell`), cell-backed statics for classes and enums, enum
    `moduleUri` identity + constant-shape retirement, module fingerprints and
    patch bundles, async continuation slicing, guest call frames, the
    collection/`Comparator` stubs, the isolate worker, and archive 3.x/4.x
    compatibility.
- **A block body that runs off its end returns `null`** (Dart semantics, since
  `tom_d4rt` 1.235.0). Fixtures that relied on the last statement's value now
  return explicitly; `AstInterpreterRunner.evaluateAstBundleAs` waits briefly
  for a late `runApp` capture, which the playground's async entrypoint needs.
- **Bridge regeneration caveat**: `tom_d4rt_generator` is vendored at 1.67.0
  (analyzer 14 is forced by `tom_d4rt` 1.279.0). Regenerating the bridges
  currently mis-emits `required` for optional named parameters that carry a
  default inside an inline function type (`FastListController`'s
  `{double alignment, Curve curve, int durationMs}` callbacks), so the
  committed `*.b.dart` files remain authoritative until that upstream issue is
  fixed. Nothing at build or run time regenerates them.
- **A library's own class shadows an imported one of the same name**
  (`tom_d4rt` 1.244.0), so two modules declaring the same private class no
  longer collide at load.
- **Renamed workspace packages to `dngo_*`**: Renamed `pkgs/dartnative_go_api` → `pkgs/dngo_api`, `pkgs/dartnative_go_config` → `pkgs/dngo_config`, and `pkgs/dartnative_go_ui` → `pkgs/dngo_ui` across the workspace, bridges, CLI, tests, and documentation.
- **Optional `SplashConfig.backgroundColor` in `dngo_config`**: `SplashConfig.backgroundColor` is now nullable (`ColorValue?`) so configs can omit an explicit splash background color.
- **Bridges regenerated for new plugins**: Updated `buildkit.yaml` and `buildkit_ast.yaml` to register `dartnative_live_activities`, `local_auth_kit`, and `quick_actions_kit`, and regenerated source and AST bridge files (`lib/src/interpreter/*.b.dart` and `ast/*.b.dart`). Updated host and example plugin registrants.
- **First-party plugins upgraded to the current DartNative SDK builds**: on DartNative 1.7.0, `dartnative_background` 1.0.1 → 1.0.3, `dartnative_connectivity` 1.0.0 → 1.0.1, `dartnative_media_picker` 1.1.0 → 1.1.2, `dartnative_notifications` 1.0.1 → 1.0.4, `dartnative_share` 1.0.2 → 1.0.4, `dartnative_splash` 1.0.1 → 1.0.2, `dartnative_system` 1.0.0 → 1.0.1, `dartnative_url_launcher` 1.0.0 → 1.0.1. Recorded in `dn_plugins.lock`. These packages resolve from the SDK cache rather than pub.dev, so `dn pub outdated` does not report them. Every upgraded plugin's Dart API surface is byte-identical to the previous release (the changes are native binaries plus version bumps, and in `notifications` a private FFI typedef), so the bridged surface is unchanged: both bridge sets were regenerated and only gained the generator's `functionTypedefArity()` stub.
- **Bridge regeneration is now format-stable**: `tool/d4rtgen.dart` and `tool/d4rtgen_ast.dart` format their generated `*.b.dart` output as a final step, and `analysis_options.yaml` pins `page_width: 80` alongside `trailing_commas: preserve`. The generator's raw layout plus the `DN-PATCH` splices previously made every regeneration a whole-file whitespace diff; re-running either driver against unchanged sources is now a no-op.
- **Workspace formatted with the pinned formatter**: one-time `dart format` sweep over `lib/`, `pkgs/`, `tool/`, `test/` and `example/lib/`, so later edits surface only real changes instead of formatter churn.
- **Error screen layout and copy payload**: `InterpreterErrorView` always titles "Unhandled Exception" (stage / exception type as subtitle). `parseStackFrames` and `buildCopyText` in `guest_error_format.dart` drive a themed, horizontally scrollable stack card and a pasteable message+trace clipboard payload.
- **Hot restart shows splash and resets state**: DevTools reload and CLI restart now clear `isAppMounted`, display the project splash during evaluation, and remount guest widgets with a bumped `guestEpoch` (`PreviewState.guestEpoch`) so State objects are fresh.
- **Launch splash transition settles before evaluation**: `_launchProject` awaits the preview route entrance transition before starting synchronous bundle evaluation, preventing frame freezes mid-animation.
- **DevTools overlay lifecycle gating**: The floating DevTools button, shake detector, and sheet are gated (`isEnabled`) until the guest app mounts, preventing unresponsive controls during loading.
- **Shell theme resolution and platform brightness sync**: `ShellThemeScope` resolves appearance inside the widget tree using `MediaQuery` with `Theme.of` fallback, reacting to device brightness switches and hydrating stored preferences across restarts.
- **AST bundles output to `.dart_tool/bundles/`**: Moved bundle build artifacts out of `assets/` into `<project>/.dart_tool/bundles/guest.ast` (with fallback to legacy paths) so large generated binaries are not tracked in git.
- **Product builds link only the AST runtime**: Split `lib/main.dart` to link only `tom_d4rt_ast` and moved the host UI shell to `lib/src/app_shell.dart`. Strips `package:analyzer`, `tom_d4rt`, and source bridges from AOT builds (~690k lines removed). Added `lib/main_source.dart` for the analyzer-based engine.
- **Decoupled breakpoint instrumentation from `AutoImportParser`**: Extracted analyzer instrumentation logic into `lib/src/interpreter/breakpoint_instrumenter.dart`, injected via typedef so source map generation remains analyzer-free.
- **Extracted `DepEntry`**: Moved pure-Dart dependency metadata into `lib/src/runner/dep_entry.dart`, keeping client caching decoupled from the server-side analyzer packaging pipeline.
- **Untyped `DebugController.activeInterpreter`**: Changed active interpreter reference to `Object?` so the AST product graph does not link `package:tom_d4rt`.
- **Capability-aware runtime modes**: Clamps runtime mode selection to AST when running the default AST-only binary; DevTools and launcher mode switches hide themselves when only one engine is linked.
- **Deterministic `user-code.zip` packaging**: Stamped fixed DOS-epoch timestamps and sorted paths in `DepPackager.zipFilesMap` so unchanged sources produce byte-stable archives and identical hashes.
- **Bridges regenerated for DartNative SDK 1.5.0**: the SDK changed `NativeBindings.registerScrollCallback`'s fourth parameter from `bool` to `int`. Every generated bridge declared the old callback type, so all `test/server_component/*` suites and `server_component_view_test` failed to compile. Both engines (`lib/src/interpreter/*.b.dart` and `lib/src/interpreter/ast/*.b.dart`) were regenerated with `tool/d4rtgen.dart` / `tool/d4rtgen_ast.dart`, and `SheetNativeBindings` in `dartnative_bottomsheet` was aligned to the new signature.
- **AST launch profile no longer serializes the whole bundle**: the bundler now records per-module, per-class and per-source byte sizes in `manifest.json` (`moduleSizes` / `classSizes` / `sourceSizes`, threaded through `AstBundle` → `applyPatch` → the `/guest.ast.patch` deltas), and `buildAstProfile` reads them instead of calling `jsonEncode(unit.toJson())` for every module and class. That walk previously ran on the launch path whenever verbose profiling was on, and its cost was invisible because it happened after the AST timer stopped. Bundles that predate the metadata never fall back on the launch path (`allowSerialization: false`): sizes are reported as unavailable instead of costing serialization time, while the DevTools AST panel still falls back on demand. The AST timer now reports `profile=` as its own field, so profile cost is visible rather than inferred.

- **Interpreted `await` no longer starves the embedder's event loop**: async continuations used to be queued exclusively as microtasks, which all drain before the embedder (DartNative) regains control — so a long chain of interpreted `await`s (dio's request pipeline, for example) blocked the UI thread for hundreds of milliseconds to seconds per request. `InterpretedFunction._scheduleStateMachineRun` now slices async work by wall-clock: while one event-loop turn stays under `InterpretedFunction.asyncSliceBudgetMicros` (default 4000µs) continuations keep the cheap microtask fast path, and once the budget is spent the next continuation is deferred to a zero-duration timer turn so a frame can be rendered in between.
